# Index预训练与Memory预训练方案

本文结合Figure的Index与Helix 2.5技术博客，整理一个待验证的方向：在VLA预训练阶段加入依赖历史的行为数据，让模型提前学习记录、更新和使用任务记忆，后训练再适配具体机器人与任务。

文中“公开信息”来自博客；“方案”和示例是本文的设计，不代表Figure或MagicVLA已经实现。

相关笔记：[MagicVLA预训练实验](MagicVLA_预训练实验.md)、[MagicVLA记忆整理](MagicVLA_记忆整理.md)、[统一数据处理笔记](../Note_DataPipeline.md)。

## 1. Index pretraining是什么

### 1.1 数据从哪里来

Index是Figure采集真实人类行为的数据平台。参与者在家庭和工作场所录制任务视频，覆盖不同任务、物体、环境和执行方式。它的价值在于扩大真实行为覆盖，而不只是积累相似场景下的重复演示。[来源：Introducing Index](https://www.figure.ai/news/introducing-index)

### 1.2 数据如何处理

Figure公开了五个处理阶段：

| 阶段 | 作用 |
|---|---|
| 质量过滤 | 检查技术、画面和语义质量 |
| 人工审核 | 按用户抽查规避过滤规则的行为 |
| 相似去重 | 将视频片段编码成向量，过滤与已有数据高度相似的片段 |
| 分布重平衡 | 结合任务配额和embedding聚类，控制数据分布 |
| 层级标注 | 为每个episode生成层级文本描述 |

任务配额控制任务之间的比例；embedding聚类补充任务名称无法表达的内部差异。层级caption提供不同粒度的描述，但博客没有公开完整字段和生成规则。[来源：Index数据流程](https://www.figure.ai/news/introducing-index)

### 1.3 预训练如何迁移到机器人

Helix 2.5从随机初始化开始，在Index上预训练，再用其他地点采集的任务数据适配整理客厅、叠毛巾和铺床。博客报告：固定架构、优化和下游数据后，Index预训练使30个未见家庭中的完整任务成功率从9%提高到56%。这里的zero-shot针对新环境和新物体，任务本身经过适配训练。[来源：Helix 2.5](https://www.figure.ai/news/helix-2-5-zero-shot-30-home-generalization)

博客还报告，扩大Index数据量会持续降低下游动作预测loss。附录通过视频embedding与片段活动、物体描述的文本embedding，分别做层级聚类，统计数据覆盖。这种统计层级不等同于模型内部的任务规划结构。[来源：Helix 2.5数据分析](https://www.figure.ai/news/helix-2-5-zero-shot-30-home-generalization)

### 1.4 可以借鉴什么

对本方案的启发是：通用能力可以在预训练阶段培养，后训练负责具体行为适配。但上述博客没有公开足以复现的预训练输入、loss、人类到机器人动作接口和memory机制，不能据此认定Index已经实现本文提出的记忆训练。

## 2. 我的想法：让预训练学习“这次发生过什么”

希望模型不仅知道任务通常怎么做，还能根据本次执行的历史调整下一步行为。例如：

- 哪些位置已经搜索，哪些尚未搜索；
- 哪些子任务已经完成，当前正在处理什么；
- 物体之前在哪里，后来是否被移动；
- 哪次尝试失败，之后是否重试成功；
- 很早以前给出的条件，现在是否仍然有效。

本文把“原生memory能力”限定为：**基座在预训练阶段就学习利用历史，并能在新任务中继续维护和使用这些信息。** 它不意味着无限记忆，也不意味着部署时在线修改模型权重。

| 概念 | 要解决的问题 | 示例 |
|---|---|---|
| 行为先验 | 这类任务通常怎么做 | 铺床一般需要拉平被子、整理枕头 |
| 任务层级 | 当前动作属于哪个目标 | 拉被角属于整理床铺 |
| 执行记忆 | 这次已经发生了什么 | 左侧处理完了，右侧抓取失败过一次 |

数据广度和历史依赖是两个可以组合的设计维度。本文借鉴Index的数据组织方法，再增加面向执行记忆的样本与监督；不据此判断Index本身缺少记忆能力。

## 3. 什么样的数据能训练memory

### 3.1 长视频只是起点

如果五分钟视频每次只截取两秒来预测局部动作，模型主要学习的仍是局部行为。即使提供长历史，当当前画面已经足够回答问题时，模型也可能忽略历史。

优先选择这样的样本：**当前画面和指令相近，但过去发生的事情不同，下一步合理行为也不同。**

例如，任务要求找到螺丝刀，当前画面中A、B、C三个抽屉都关着：

| 历史 | 下一步合理行为 |
|---|---|
| A、B已检查为空，C未检查 | 优先检查C |
| A、C已检查为空，B未检查 | 优先检查B |

前提是搜索期间物体没有被他人移动，历史观测也足够可靠。否则旧记忆应允许失效，不能把“查过”永久等同于“无需再查”。

### 3.2 优先收集的样本

| 类型 | 需要保留的历史 | 可用监督 |
|---|---|---|
| 搜索与重访 | 已检查区域、检查结果 | 未搜索区域、下一搜索目标 |
| 任务进度 | 已完成的子任务 | 当前阶段、已完成集合 |
| 物体状态变化 | 物体被放置、移动的事件 | 最后确认位置与时间 |
| 失败与恢复 | 失败原因、重试过程 | 尝试状态、后续行为 |
| 延迟条件 | 早期指令或关键观察 | 当前应遵循的条件 |

这些类型是候选来源，不保证每个片段都依赖memory。例如当前图像已经清楚显示抓取失败的样本，可能只需要即时视觉反馈。

## 4. 标注如何组织

### 4.1 层级关系与事件关系分开记录

建议采用“任务→子任务→事件”三层结构；同一任务内部，再记录物体状态和事件之间的关系。

| 层次 | 建议字段 | 用途 |
|---|---|---|
| Episode | episode_id、任务、场景、数据源 | 保留完整执行上下文 |
| Subtask | subtask_id、parent_id、起止时间 | 表达任务层级和阶段 |
| Event | event_id、时间、对象ID、事件类型、结果 | 记录发生了什么 |
| Relation | before、requires、updates、retry_of | 表达顺序、前置条件、状态更新和重试 |
| Evidence | 证据帧、置信度、未知标记 | 区分观测事实和推测 |

before只表示先后，不自动表示因果。requires等逻辑关系需要任务规则或可靠证据支持；不要让标注模型仅凭常识补出视频中不存在的过程。

对象ID需要在同一episode内保持一致。状态随事件更新，例如“抓取失败→重试成功”之后，应记录为已成功，失败只保留为历史事件。

### 4.2 一个训练样本

以下是建议的数据组织形式，字段不是现有pipeline接口：

~~~yaml
episode_id: search_001
anchor_time_s: 60
instruction: 找到螺丝刀
inputs:
  history: [检查A的片段, 检查B的片段]
  current: 三个抽屉均关闭的画面
targets:
  task_state:
    checked_empty: [drawer_A, drawer_B]
    unchecked: [drawer_C]
  next_subtask: 检查drawer_C
evidence:
  drawer_A: {time_s: 20, event: 检查为空}
  drawer_B: {time_s: 45, event: 检查为空}
~~~

task_state首先作为预测目标。若直接把正确的历史摘要塞进输入，模型可能只学会读取答案，而没有学会从历史中建立记忆。

### 4.3 防止未来信息进入输入

1. 历史只能来自当前anchor之前；当前帧可以作为独立观测输入。
2. 任务状态标注只能描述截至当前时刻已经观察到的事实。尚未查看的抽屉应标为未知。
3. 下一子任务、未来事件和action chunk可以作为预测目标，不能提前进入历史摘要。
4. 历史片段不完整时，只监督能够从所给输入判断的字段，其他字段屏蔽或标为未知。
5. 人工摘要若用于训练输入，部署时也需要模型生成或维护摘要，并评估累积错误。

## 5. 训练方式

### 5.1 先学习历史，再学习如何利用历史行动

初期可以沿用历史帧输入，先验证数据是否有效；之后再考虑固定数量的memory token或递归状态。

~~~text
历史观测 + 当前观测 + 任务指令
                ↓
          历史编码或记忆模块
                ↓
             共享表示
          ↙             ↘
任务状态、关键事件       下一子任务或动作
~~~

任务状态可以作为辅助监督，不必强制动作头经过一段文本摘要。关键是部署时动作分支能读取同一份历史表示，且预训练中这条路径实际参与学习。

仅扩大上下文窗口不保证获得长期记忆。使用递归状态时，还要训练跨片段的状态传递，并在episode边界清空；否则容易出现训练和部署不一致。

### 5.2 按标签能力使用异构数据

| 数据 | 初期训练目标 | 注意事项 |
|---|---|---|
| 普通人类视频 | 历史问答、任务状态、事件与下一子任务预测 | 没有机器人动作真值时，不构造伪joint标签 |
| 带可靠手部或EEF轨迹的数据 | 上述目标，以及有效轨迹预测 | 保留坐标系、有效mask和动作版本 |
| 机器人长轨迹 | 动作预测，加任务状态或事件辅助监督 | 检查历史信息是否真正影响动作输出 |

总训练目标可以由行为预测、任务状态和事件预测组成，权重通过消融选择。缺少某类标签时屏蔽对应loss，避免把未知状态当成负例。

初期只增加一两个辅助目标，例如“已检查区域”和“下一子任务”。同时混合普通操作数据，避免memory专项训练降低基本操作能力。32D与34D动作版本继续独立维护。

### 5.3 标注与采样流程

~~~text
保留episode与时间顺序
          ↓
质量检查、分段、对象关联
          ↓
生成层级描述与事件标注
          ↓
筛选依赖历史的anchor并人工抽查
          ↓
构建历史输入、监督目标和证据索引
          ↓
按任务、依赖类型、时间跨度混合采样
~~~

去重时需要保留前后文关系。两个当前画面即使高度相似，只要历史不同、正确行为不同，就可能是有价值的成对样本，不能仅按当前图像相似度删除。

## 6. 如何验证想法

### 6.1 先回答“提前训练是否有用”

使用同一批episode、相同模型容量和尽量一致的训练计算预算，比较：

| 组别 | 预训练设置 | 要回答的问题 |
|---|---|---|
| A | 只提供局部观测，训练行为预测 | 当前观测基线是多少 |
| B | 提供历史，保持相同的行为目标 | 增加历史输入是否足够 |
| C | 在B上增加结构化状态与事件监督 | 标注是否改善历史使用 |
| D | 在C上增加历史依赖样本的采样权重 | 样本组织是否进一步有效 |

所有组使用相同的下游memory后训练配方和数据预算，再比较新任务上的成功率与学习速度。A组在后训练阶段开放同样的历史接口，作为“memory主要在后训练学习”的对照。记录各组token数与计算量，避免把更多计算带来的收益归因于memory。

### 6.2 验证模型确实使用历史

- **移除历史**：依赖历史的任务应出现性能下降；不依赖历史的任务作为对照。
- **替换历史**：使用真实、语义一致的成对样本，检查预测是否随历史正确变化。
- **删除关键事件**：比较删除关键事件与删除等量无关片段的影响。
- **延长间隔**：在关键事件和决策之间加入真实干扰过程，观察信息保持能力。

单纯删除或打乱历史可能造成输入分布变化，不能只凭一次性能下降证明模型学会了记忆。需要结合成对样本、状态预测和闭环行为判断。

### 6.3 评测指标与数据划分

关注完整任务成功率、重复搜索率、遗漏子任务数、失败恢复率，以及任务状态预测准确率。动作loss下降只能作为辅助证据。

按完整episode划分数据，并进一步隔离场景、采集者或任务组合；相邻片段和同一事件的多个视角不能跨训练与测试集。专用memory评测集也要从预训练数据中排除。

## 7. 第一阶段怎么做

1. 先选“搜索过哪些位置”和“哪些子任务已完成”两类任务，建立小规模人工核验集。
2. 保留episode、时间戳和对象ID，只补关键事件、状态变化与证据帧。
3. 使用现有历史输入方案完成A/B/C对比，暂不叠加复杂动态记忆机制。
4. 先验证历史改变时输出能否正确改变，再扩大预训练数据和时间跨度。
5. 用相同后训练预算评估迁移收益；有效后再扩展到失败恢复、事件压缩和递归记忆。

目前需要验证的核心假设是：**从预训练开始使用依赖历史的数据与结构化监督，能否比只在后训练加入memory，更容易学到可迁移的执行记忆。** 标注数量、历史长度和模块复杂度都应围绕这个问题逐步增加。
