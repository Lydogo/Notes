# 视觉记忆方案对比

## 1. 先看结论

两套方案都使用固定长度的历史视觉输入，但接入位置不同：

| 方案 | 基础模型 | 历史帧 | 接入位置 | 主要特点 |
|---|---|---|---|---|
| MagicVLA v0/v1 | Qwen3.5-2B VLA | 6 帧，间隔 1 秒 | Vision tower 内做时空融合，再进入语言侧 | 端到端视觉记忆；v1 用 time-then-space attention |
| π0.5 FrameSamp+Modul | π0.5 flow VLA | `cam_high` 历史帧，最多 32 帧 | 只进入 action expert 的 memory cross-attention | 不改变原 VLM prefix；离线缓存 SigLIP 特征 |

## 2. 数据流差异

```text
MagicVLA:
多视角历史 RGB → 视觉塔时空注意力 → 当前帧视觉表示 → VLA 主干

FrameSamp+Modul:
cam_high 历史 RGB → 离线 SigLIP → 4×4 pooling → 512 memory tokens
→ action expert 的 MemoryAttention / modulation
```

MagicVLA 的历史信息影响视觉表示本身；FrameSamp 的历史信息绕过 VLM prefix，只调节 action expert。两者的 attention、延迟和 ablation 不能直接横向比较。

## 3. 尺寸与计算

| 项目 | MagicVLA | FrameSamp+Modul |
|---|---:|---:|
| 观测帧数 | 6 | 最多 32（每帧 16 token） |
| 记忆 token | 由视觉塔内部融合 | 固定 512 |
| 单帧 patch | 256（16×16） | 4×4 pooling 后 16 |
| 视觉 hidden | 1024 → merger 2048 | SigLIP 2048；memory 1024 |
| 位置编码 | 视觉塔自身时空注意力 | RoboMME 3D 时间/空间位置编码，768 维 |
| 推理状态 | 每步显式提供历史窗口 | 当前代码主要覆盖训练链路，推理侧仍需补齐 |

## 4. 什么时候选哪条路线

- 需要让历史信息参与通用视觉理解时，优先考虑 MagicVLA 这类视觉塔内融合。
- 只希望增强动作 expert、保持原 VLM prefix 不变时，FrameSamp+Modul 更容易做增量实验。
- 需要严格控制 action expert 的 memory 长度时，固定 512 token 的 FrameSamp 更直接。
- 需要跨相机、跨任务解释“模型看到了什么”时，两种方案都应配合 attention 与闭环成功率实验，不能只看 memory 是否接入。
